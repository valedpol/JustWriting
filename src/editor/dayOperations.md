# Операции редактора на границе дня

Этап 4 добавляет headless-адаптер, без подключения к App или useTodayText.
`dayOperations.js` фиксирует операции и извлекает вставленные Slice;
`daySession.js` связывает их с существующими resolveToday, saveRichText,
endWritingSession и sampleWordCount. Доменные правила не дублируются.

## Контракт операций

`openDaySession({ profile, now, sessionId, getProfile })` загружает доступный
документ. При reload sessionId не передаётся: адаптер никогда не восстанавливает
его из IndexedDB. При первом реальном действии создаётся новый ID в памяти.
Для продолжающейся сессии можно передать её существующий ID. getProfile позволяет
получать актуальные настройки из уже существующего состояния приложения.

`dispatch(transaction, { kind, id, acceptedAt })` обрабатывает одну операцию.
kind различает input, paste, composition, delete, format, undo, redo,
selection-markup, slash-markup, semantic и selection. acceptedAt фиксируется при
приёме операции, а не после ожидания сохранения. Операции, проверки дня и выход
из сессии выполняются последовательно. flush ожидает завершения очереди;
отдельные промисы операций сообщают об ошибках, pendingFailure хранит причину
и саму операцию. Повтор после ошибки выполняется только через retry(id).

Для оптимистического UI можно отдельно вызвать capture и submit. Следующая
операция должна получить source с afterState предыдущей операции, даже если её
сохранение ещё ожидается. Подтверждение записи не требует setContent и не
пересоздаёт состояние редактора. Вызовы с устаревшим состоянием того же дня
отклоняются; чужая revision не подставляется в saveRichText автоматически.

id обозначает одну логическую операцию и не должен использоваться для другого
ввода. Повторная доставка с тем же id возвращает тот же промис без повторной
записи. Реестр действует только в памяти этой сессии; это не протокол серверной
синхронизации. Ошибка дополнительной статистики возвращается как samplingError
и не превращает успешное сохранение текста в неудачную операцию.

## Переход дня

resolveToday выбирает целевой день по времени операции и её sessionId.
При разрешённой grace используется прежний EditorState с общей историей.
При переходе дня загружается сохранённый документ нового дня и создаётся новая
история. Старые ProseMirror steps, selection и смысловые позиции на него не
применяются.

Для input, paste и завершённой composition переносится только вставленная часть.
Её происхождение отслеживается по ReplaceStep и StepMap; итоговые Slice берутся
из соответствующих диапазонов результата. Это сохраняет marks, абзацы и
hardBreak, исключает промежуточные IME-строки и старый текст между вставками.
Поступающий paste должен быть уже очищен существующим cleanPaste и разобран
схемой редактора. Адаптер не интерпретирует HTML.

Фрагменты добавляются в конец актуального документа нового дня через его
собственные позиции. Если документ уже существует, он сохраняется вместе со
своей разметкой. Undo переносимой операции может убрать только новую вставку.
Старый Undo/Redo определяется также через isHistoryTransaction, поэтому даже
ошибочная классификация как input не переносит восстановленный старый текст.

Удаление, B/I/U и смысловые операции над закрытым документом возвращают
not-applied / old-day-operation, не создают новый texts и не изменяют чужие
диапазоны. Старые selection-диапазоны и slash-точки не переносятся. Значение
незавершённой slash-команды передаётся как semanticDraft; при переходе оно
возвращается в drafts без anchor/range, для явного дальнейшего решения UI.
Новая slash-сущность, подтверждённая на границе, также сохраняет значение в
этом отдельном черновике, а не получает автоматическую привязку к новому дню.

## IME и порядок завершающих событий

beginComposition(id, source) фиксирует начало. updateComposition(id, transaction)
принимает последовательные транзакции относительно возвращённого им состояния.
Промежуточное состояние предназначено для отображения UI и не сохраняется.
Проверки check, запрошенные во время композиции, откладываются даже тогда,
когда их callback очереди запускается уже после завершения композиции.

finishComposition(id, { transaction, acceptedAt }) вызывается после получения
финального редакторского фрагмента; последнюю транзакцию можно передать прямо
в этот вызов. Время завершения определяет маршрут относительно grace. Нельзя
завершать композицию по одному лишь DOM compositionend, если браузер ещё не
доставил финальную редакторскую транзакцию: согласование DOM-событий относится
к будущему подключению UI. Все уведомления об одном завершении должны сохранять
тот же id. Повторные finishComposition/dispatch с этим id не записывают текст,
а поздний updateComposition с уже завершённым id игнорируется.

Полностью отменённый preedit не повышает revision и не создаёт Undo-событие.
Сравнение doc.eq здесь используется лишь для обнаружения отсутствия изменения;
маршрутизация между днями не основана на сравнении JSON/HTML.

Автоматические тесты используют настоящие репозитории поверх fake-indexeddb и
транзакции ProseMirror. Реальные DOM-последовательности IME в Chrome/Safari
проверяются при подключении основного редактора на следующем этапе.
